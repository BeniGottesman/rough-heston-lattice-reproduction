# n <-> m : how many lift factors a grid of n steps needs

`ALGO_VERSION` 1.1.1 · `code_sha` 6b5cf0db492c

Criterion throughout: the RELATIVE kernel error on the lags the
scheme actually sees,

    rel(m) = ||K - K^m||_{L2(delta,T)} / ||K||_{L2(delta,T)},   delta = T/n.

Relative, so it is independent of the kernel's normalisation; on
(delta,T), because no lattice with step delta evaluates K closer to
the origin than delta.  Values printed as `<1e-04` are below the
cancellation floor of the exact L2 formula and mean *unresolved*,
not zero.  All tolerances used are far above that floor.

## 3. The mechanism: does a fixed node ratio buy a fixed accuracy?

The explicit construction covers [1/T, 1/delta] with a fixed ratio r
between consecutive nodes, so `m = 1 + ceil(log n / log r)` holds
identically.  If the error at fixed r does not grow with n, then the
log law is a consequence and not a fit: covering a range of n at a
bounded cost per node costs log n nodes.

## 6. What this is NOT

- **Not a bound.** Every entry is a measurement, and the log law is a
  fit with its residuals shown. The `m` sufficient side is reachable
  from section 3 with an explicit node placement; the `m` necessary
  side (that no m-factor lift with positive weights does better) is
  not measured here beyond the `best` construction's local search.
- **Not a price error.** Propagating a kernel error to a price error
  goes through Proposition (B1'), whose constant is unevaluated. Until
  it is, `rel(m) <= tol` does not license any statement about a price.
- **`best` is a local search**, warm-started from m-1; it is a 'best
  found', so it is an upper bound on the achievable error and its m*
  is a lower bound on what is necessary only up to that search.
